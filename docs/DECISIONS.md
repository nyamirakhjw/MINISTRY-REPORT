# Decisions and deviations

| # | Decision | Reason |
|---|---|---|
| ADR-1 | **Hand-written service worker** (`public/service-worker.js`) instead of Serwist | Keeps the PWA skeleton independent of a bundler plugin that could not be tested here. It caches only static assets and an offline page and never touches personal data. Revisit in Phase 2 when the offline queue needs precache manifests |
| ADR-2 | **No TanStack Table**; small sort and filter logic in the reports table | At a few hundred rows it is simpler and lighter. Revisit if tables grow |
| ADR-3 | **Native `<select>`** styled with tokens | Best keyboard and screen-reader behaviour on Android, no extra JavaScript |
| ADR-4 | **Brevo HTTP API** for the app's own emails (Edge Function); Supabase Auth still uses SMTP | `fetch` is the most reliable transport in the Edge runtime. Same Brevo account. Swap the `sendEmail` function to change provider |
| ADR-5 | **Server actions and server components** call the database under the user's session; the browser talks to Supabase only for Storage uploads and Realtime | Smaller client bundle, one place for error mapping. RLS still applies |
| ADR-6 | **Realtime is a signal to refetch** (`useLiveRefresh`), never the source of truth | PRD §14.5. The app works if Realtime is down |
| ADR-7 | **Elder console**: top tab strip below 768px, left rail from 768px | Matches the PRD navigation intent with one shared item list |
| ADR-8 | **Delivered early** (small, no extra infrastructure): overview KPIs and category totals (ADM-01, 02), WhatsApp click-to-chat (part of ADM-07), audit-log search | They reuse data the Phase 1 screens already load |
| ADR-9 | **Hardening fixes to Appendix A SQL**: request id must belong to the caller; Ministerial Servants can read pending photos in Storage; explicit `hours_required`; deny-by-default grant sweep; `not_reported` months can be reversed by submitting on behalf | Found while turning the reference schema into migrations |
| ADR-10 | **`recovery_codes` and `profile_change_requests` tables added** | Required by AUTH-09 (hashed recovery codes) and PRO-04 (name and username change requests); not in the PRD data model |
| ADR-11 | **Kiswahili gated by `NEXT_PUBLIC_ENABLE_SW`** | Gate G-6: nothing in draft Kiswahili reaches members |
| ADR-12 | **Landing meeting times and address come from settings and are hidden until real values exist** | PRD rule: no invented content |
| ADR-13 | **First launch runs without custom SMTP**, with "Confirm email" turned off in Supabase | The Owner chose speed over gate G-1 for the initial go-live, with a single Elder. `requestAccessAction`/`RequestAccessForm` handle both cases (email confirmation on or off) so this is a config toggle, not a code fork. Traded away: self-service password reset (replaced by the Elder recovery link, which needs no email) and email delivery of approval/rejection notices (in-app notification still fires). Revisit before congregation-wide launch — gate G-1 still applies before real volume |
| ADR-14 | **Daily log works fully offline for adding hours; editing and deleting an entry need a connection** | LOG-07 only requires that *logging hours* works offline (the field case that matters — no signal while out in service). A generic conflict-resolving edit/delete-offline path is real work better shared with the report-draft and return-visit offline queues in a later slice, rather than built three times |
| ADR-15 | **Landing redesign "The Open Door"**: a gold doorway of light opens once behind the logo mark, gold stays a thin edge, one live labelled sample of the hours ribbon | PRD v1.1 §3 to §4. Built on the new illustrated logo; the old shield wording in PRD v1.0 §11 is superseded |
| ADR-16 | **Landing motion is pure CSS** (keyframes, scroll-driven timelines with an `IntersectionObserver` fallback, View Transitions for the theme change). No animation library on the landing route. `motion` is reserved for the signed-in app in a later slice | Zero JavaScript cost on the most visited page; every animation has a reduced-motion path (PRD v1.1 §6) |
| ADR-17 | **Public pages skip the auth round trip in the proxy, and the landing reads the congregation through a five-minute cache** (anon client, no cookies; expired at once when Elders save settings) | The page shows nothing about the signed-in person, so it needs neither. Exact-match allow-list in `proxy.ts`; a Playwright test confirms every private area still redirects. The nonce CSP still makes the page render per request (PRD v1.1 F-04) |
| ADR-18 | **Logo ships as two small WebP files in `public/brand/`** (128 and 394 px wide) generated from `brand-src/mark-only.png`; the 467 KB PWA icon is no longer used in the header | The header was loading the PWA icon on every page |
| ADR-19 | **App motion needs no new dependency.** The planned `motion` library is not added: the ribbon, toggle, collapse, dialogs and highlights are CSS transitions and keyframes plus two small Web Animations calls. Numerals are written straight to a DOM node, never through per-frame state | PRD v1.1 §6.3 allowed the library for presence and layout; nothing in this slice needs it, so the bundle and the lockfile stay untouched. Revisit if list reordering or swipe gestures (AM-16) are built |
| ADR-20 | **Report card built** (it was specified in PRD §7.8 but not in the repo): drawn on a canvas on the device, never stored, no public link, re-downloadable from History at `/app/card/<yyyy-mm>` | The "report card moment" needed a card to animate. Offline, the photo falls back to initials until the image has been cached |
| ADR-21 | **Live highlights are a refetch signal, not truth**: rows that are new or changed since the previous render get a one-off gold wash; items present when a page opens never flash | Matches PRD §14.5 (live events trigger a refetch). Queue items use `LiveList` and `LiveItem`; the reports table uses `useRowFlash` |
| ADR-22 | **Page transitions use `template.tsx`, not the View Transitions flag**: the member app rises 4px as it fades, the Elder console only fades. A language change and the theme change use the browser's View Transitions API where it exists | `template.tsx` re-mounts on every navigation, needs no experimental Next flag and cannot break routing. `waitFor` polls with timers because the browser pauses animation frames while a view transition waits |
| ADR-23 | **Visit swipe**: dragging a return visit left past 72px opens the "log this visit" dialog and the card springs back; a visible "Mark visited" button does the same for keyboard and screen-reader users | Marking a visit needs an outcome and a next date, so the swipe opens the dialog instead of silently saving. Position is written to the element, never held in state |
| ADR-24 | **Elder console motion stays light**: the overview numbers count up once per browser session and then update instantly; charts draw in on first render only; downloads show a ring then a check, and a failed export shows a readable message | Matches PRD v1.1 §7.3: used all day, so nothing replays on live refreshes or month changes |
